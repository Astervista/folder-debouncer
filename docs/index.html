How it works

Your dev server runs in a mirror. You hold the gate.

On start, folder-debouncer mirrors your project into a second folder. The sources you choose are copied; everything else, from node_modules to angular.json, is a symlink and always live. Edits to the sources are snapshotted and queued, then written to the mirror in one burst when you flush.

  • angular.jsonlinked

Setup

Three steps, no changes to your build.

It works with any watcher because it never touches the tool. It only controls what the tool gets to see.

Create the config

In your project. The default holds back src/ and mirrors into a sibling folder.

$ cd my-app
$ debouncer --init
$ debouncer

Run your dev server in the mirror

Any watcher works: the Angular CLI, tsc --watch, webpack, Vite, nodemon, test runners.

$ cd ../my-app-debounced
$ npx ng serve
# or npx tsc --watch, npm run dev…

Edit, then flush

Edit my-app as usual. When the change is ready, flush from a key in your editor, or press F in the dashboard.

$ debouncer --flush
Flush requested (.debouncer-flush).
Editor shortcuts

Flush without leaving your editor.

Bind debouncer --flush to a key. It writes the trigger file, and the running instance sends everything that is saved on disk.

  1. Open Settings | Tools | External Tools and click +.
  2. Set Name to Flush debouncer, Program to debouncer, Arguments to --flush and Working directory to $ProjectFileDir$. Under Advanced Options, clear Open console for tool output.
  3. In Settings | Keymap, find External Tools | Flush debouncer and add a shortcut, for example ⌥ ⌘ ↵.

If the IDE can't find the command, put the full path from which debouncer in Program.

Add a task in .vscode/tasks.json:

{
  "version": "2.0.0",
  "tasks": [{
    "label": "Flush debouncer",
    "type": "shell",
    "command": "debouncer --flush",
    "presentation": {"reveal": "never"},
    "problemMatcher": []
  }]
}

Then bind it in keybindings.json:

{
  "key": "alt+cmd+enter",
  "command": "workbench.action.tasks.runTask",
  "args": "Flush debouncer"
}

Anything that can run a command or touch a file can flush: a Raycast or Alfred command, a git hook, the end of a script.

$ debouncer --flush
# or, from the project folder
$ touch .debouncer-flush
Why not just…

The usual fixes only delay the problem.

ApproachWhat goes wrong
Turn off autosaveJetBrains IDEs still save when you switch windows, run, or use version control. And you lose autosave.
Rebuild delayswebpack's aggregateTimeout and polling only postpone the rebuild. Pause for a second mid-edit and it rebuilds anyway.
Restart the dev serverSlow, and you lose incremental builds.
Tool-specific APIsOne bundler at a time, and ng serve and tsc --watch have no manual mode.
folder-debouncerWorks with any watcher, keeps autosave and live reload, and rebuilds exactly when you flush.
The dashboard

See what's waiting at the gate.

A small full-screen terminal app shows every queued change, every flush, and the state of the gate. F flushes, R reloads the config, H shows help.
